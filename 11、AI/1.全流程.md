### 🧱 第零层：AI 的“地基”（神经网络 & Transformer 架构）
**核心目标：搞懂大模型到底是“什么东西”。**
这一层是所有概念的物理基础。不懂这层，上面四层都是“黑盒咒语”。

*   **神经网络基础**：神经元、权重（Weight）、偏置（Bias）、激活函数（ReLU/GELU）。本质就是一个巨大的、可调参数的数学函数 `y = f(x)`。
*   **Transformer 架构**：现代大模型的“发动机”。一篇 2017 年的论文《Attention Is All You Need》奠定了一切。
    *   **Attention（注意力机制）**：模型读句子时，自动判断“哪些词更重要、词与词之间如何关联”。这是大模型能“理解上下文”的核心魔法。
    *   **Self-Attention / Multi-Head Attention（自注意力 / 多头注意力）**：让模型从多个角度同时理解一句话。
    *   **位置编码（Positional Encoding）**：因为 Attention 本身不分先后顺序，需要额外告诉模型“词的位置”。
*   **架构流派**：
    *   **Decoder-Only（GPT 系）**：擅长“生成/续写”，是当今主流（ChatGPT、Claude、DeepSeek 都属于这类）。
    *   **Encoder-Only（BERT 系）**：擅长“理解/分类”，常用于 Embedding、文本分类。
    *   **Encoder-Decoder（T5 系）**：擅长“翻译/摘要”这类“输入→输出”转换任务。
*   **Token（词元）**：模型眼里的“最小单位”。它不是“字”，而是经过 **Tokenizer（分词器，常用 BPE 算法）** 切分出的片段。**模型按 Token 计费、按 Token 计算上下文长度**——这是后面 L2/L4 成本的根源。
*   **参数量（Parameters）**：即权重的数量（7B = 70 亿）。参数越多，通常越“聪明”，但也越“吃显卡”。
*   **Scaling Law（缩放定律）& 涌现能力（Emergent Ability）**：模型在“数据量+参数量+算力”同时变大到一定程度后，会突然“开窍”，出现小模型没有的能力（如推理、举一反三）。

### 🏗️ 第一层：模型的“孕育”与“调教”（训练 & 微调）
**核心目标：造出一个“有常识、又听话”的大脑。**
这一层决定了 AI 的“智商”和“知识储备”。

*   **预训练（Pre-training）**：喂给模型海量数据（全网公开文本），让它通过“猜下一个词”的游戏，学到语言规律和世界常识。这就是**“几千亿次计算”**的源头。产物是一个**基座模型（Base Model）**，像个“野生的天才”，会接话，但不一定听你的话。
*   **监督微调（SFT）**：用“问答对”数据（Q&A）对基座模型进行“教学”，让它学会“提问-回答”的格式。这是从“野生”到“家养”的第一步。
*   **对齐 / 偏好优化（Alignment）**：让模型说“人话”、符合人类价值观。
    *   **RLHF（人类反馈强化学习）**：训练一个**奖励模型（Reward Model）**给答案打分，再用强化学习（PPO）让 AI 追求高分。这是 **ChatGPT** 比普通基座更“懂事”的秘密。
    *   **DPO（直接偏好优化）**：RLHF 的“简化平替”，不用单独训奖励模型，直接用“好答案 vs 坏答案”数据对齐，工程上更简单稳定，是目前的新主流。
*   **微调（Fine-tuning）**：用**公司内部数据**（如客服对话记录、特定代码库）去“补课”，让模型成为某个领域的专家。相比预训练，微调成本极低。
    *   **全参微调 vs PEFT（参数高效微调）**：全参微调改所有权重（贵）；**PEFT** 只改一小部分。
    *   **LoRA / QLoRA**：PEFT 的当红代表。**LoRA** 用“小补丁矩阵”微调，省显存；**QLoRA** 在 LoRA 基础上叠加量化，单张消费级显卡就能微调大模型。**这是中小团队微调的首选方案。**
*   **训练核心机制（每个都该懂直觉）**：
    *   **损失函数（Loss）**：衡量“模型答案”和“标准答案”的差距。
    *   **梯度下降（Gradient Descent）+ 优化器（Adam）**：根据 Loss 一点点调整参数，让模型越来越准。
    *   **学习率（Learning Rate）/ Epoch / Batch Size**：训练过程中的关键“旋钮”。
    *   **过拟合 / 欠拟合（Overfitting / Underfitting）**：背答案（死记硬背）vs 没学会；用 **Dropout / 正则化 / 早停** 来对抗。
*   **关键评估指标（你问的 Precision/Recall）**：在训练和微调后，用**验证集**测试模型。
    *   **Precision 低** → 模型“误报”多（总把好人当坏人）；**Recall 低** → “漏报”多（总让坏人溜走）；**F1-Score** 是二者综合。
    *   **数据集划分**：训练集 / 验证集 / 测试集，三者不能混用。
    *   **大模型专属评估**：Perplexity（困惑度）、MMLU / GSM8K 等 Benchmark、以及 **LLM-as-a-Judge（用大模型当裁判打分）**。

### ⚙️ 第二层：模型的“调用”与“控制”（推理 & 采样）
**核心目标：在固定的大脑上，控制“输出风格”“稳定性”和“成本”。**
你花钱调 API 时，实际操作的正是这一层。**模型参数一动不动**，只是调整“读取方式”。

*   **推理（Inference）**：输入你的 Prompt，模型执行前向传播，逐字预测概率。
    *   **两个阶段**：**Prefill（预填充，并行处理你的输入）** 和 **Decode（逐字生成输出）**。理解这两阶段，才懂为什么“首字慢、后续快”。
    *   **KV Cache**：把已算过的中间结果缓存起来，避免重复计算，是大模型推理加速的核心。
*   **采样策略（Sampling Strategies）**：控制“选哪个字”的规则。
    *   **Temperature（温度）**：**“胆量旋钮”**。低（0.1）→ 只选最稳妥的词（适合代码/数学）；高（1.0）→ 敢选生僻词（适合写诗/脑暴）。
    *   **Top-K**：**“候选人数量锁”**。只允许概率最高的前 K 个词参与抽奖。
    *   **Top-P（核采样）**：**“动态候选池”**。按概率从高到低累加，直到累加到 P 阈值（如 0.9），只允许圈里的词参与抽奖（工业界首选，非常灵活）。
    *   **惩罚项（Frequency / Presence Penalty）**：抑制“车轱辘话/复读机”现象。
*   **提示工程（Prompt Engineering）**：不改模型，靠“怎么问”就能大幅提升效果（性价比最高的技能）。
    *   **Zero-shot / Few-shot**：不给例子 / 给几个例子。
    *   **CoT（思维链）**：让模型“一步步想”，显著提升推理/数学能力。
    *   **System Prompt vs User Prompt**：用系统提示设定角色与规则。
    *   **结构化输出（JSON Mode / Structured Output）**：强制模型按固定格式返回，方便程序解析。
*   **上下文窗口（Context Window）**：模型一次能“看”的最大 Token 数。超了就会“忘记前文”——这是 RAG（L3）存在的重要原因之一。
*   **幻觉（Hallucination）**：推理时，如果 Temperature 太高或资料不足，模型会“编造事实”。**Grounding（事实锚定）** 与 RAG 就是用来对抗幻觉的。

### 🧠 第三层：模型的“四肢”与“外挂”（RAG & Agent）
**核心目标：让 AI 能查实时资料、能干具体活、能记住事。**
单靠模型内部的“记忆”（参数），无法实时更新数据，也无法操作外部软件。于是有了这一层。

*   **RAG（检索增强生成）**：**“开卷考试”**。先检索外部知识库，再把资料塞进 Prompt 让 AI 回答。完整链路：
    *   **文档清洗 → Chunking（分块）**：把长文档切成小块。分块策略（按字数/按语义/重叠窗口）直接决定召回质量，是 RAG 第一个大坑。
    *   **Embedding（向量化）**：把文本变成一串数字向量，存入 **向量数据库（Vector DB）**。
    *   **检索（Retrieval）**：**向量检索（语义相似）** + **关键词检索（BM25）** = **混合检索（Hybrid Search）**，召回更全。
    *   **Rerank（重排序）**：把初筛的 Top-100 精排成 Top-3，把最相关的排第一，是提升准确率的关键一步。
    *   **进阶**：GraphRAG（知识图谱增强）、Agentic RAG（让 Agent 自主决定检索什么）。
*   **Agent（智能体）**：**“会自己动脑动手的 AI”**。不只“回答问题”，还会“规划步骤”。比如“订机票”，它会自己规划：查日期 → 比价格 → 调支付接口。
    *   **核心范式 ReAct**：**Reasoning（思考）+ Acting（行动）** 交替循环——想一步、做一步、看结果、再想下一步。
    *   **规划与反思（Planning & Reflection）**：先拆解任务，做完再自我检查纠错。
    *   **记忆（Memory）**：**短期记忆**（当前对话上下文）+ **长期记忆**（把历史存进向量库随用随取）。
    *   **多智能体（Multi-Agent）**：多个 Agent 分工协作（如“规划者 + 执行者 + 审查者”）。
*   **Tool / Function Calling**：Agent 的“手脚”。AI 通过 API 调用外部函数（如查天气、发邮件、查数据库）。
*   **MCP（模型上下文协议）**：**“工具调用的 USB-C 接口”**。以前每接一个新工具都要写适配代码，MCP 统一了协议标准，让 Agent 能以标准方式挂载和使用外部工具。
*   **Skill（技能）**：为完成特定任务封装好的**业务级操作单元**（如“发送企业微信消息”），底层依赖 Tool，但更偏业务层。
*   **编排框架（Orchestration）**：
    *   **LangChain / LlamaIndex**：搭建 RAG/Agent 的“积木库”。
    *   **LangGraph**：用**状态机/图**编排复杂的多步骤、带循环和分支的 Agent 流程（你最终要用的）。
    *   **Workflow vs Agent**：流程固定用 Workflow（可控、便宜）；需要灵活自主决策才用 Agent（强大、但难控、贵）。

### 🚀 第四层：工程落地与运维（构建 AI 客服的全流程）
**核心目标：把上述各层串起来，稳定、快速、安全、可观测地上线一个真实产品。**
这是你最终的目标，我们把知识点全串一遍。

1.  **数据准备与微调（L1）**：收集历史客服对话，用 **LoRA** 微调基座模型，初步具备“客服语气”。
2.  **知识库构建（L3 + RAG）**：
    *   清洗 1 万份 PDF 说明书（去页眉、粘合跨页段落）→ **Chunking**。
    *   调用 **Embedding 模型**将文本分块向量化，存入**向量数据库**（热数据层），原始 PDF 存 OSS（温数据层），元数据存 MySQL（冷数据层）。
3.  **推理与控制（L2）**：用户提问时设置 **Temperature = 0.3**（严谨不跑偏）、**Top-P = 0.9**，并用 **System Prompt** 约束角色与边界。
4.  **检索与精排（L3）**：用户问题先走**混合检索**（捞出 Top-100），再走 **Rerank**（精排 Top-3），确保大模型只看到最准确的几页说明书。
5.  **流程编排（L3 + LangGraph）**：用 **LangGraph** 构建状态机。
    *   节点 A：识别用户意图（售前咨询 / 售后投诉？）。
    *   节点 B：若“查订单”，调用 **MCP/Tool** 连接公司内部订单 API。
    *   节点 C：若“转人工”，挂起流程，触发工单系统。
6.  **模型部署（Serving）**：用 **vLLM / TGI / Ollama** 部署模型，关注 **GPU 显存（VRAM）**、并发能力。云 API vs 私有化部署如何取舍。
7.  **安全与护栏（Guardrails）**：防 **Prompt 注入（Prompt Injection）**、敏感词过滤、输出合规审核、PII 脱敏——客服场景的红线。
8.  **降本提速（Optimization）**：**语义缓存（Semantic Cache）** 命中重复问题、模型量化（INT8/INT4）、小模型路由（简单问题走便宜模型）。
9.  **可观测与评估（LLMOps）**：用 **LangSmith / Langfuse** 做全链路 **Tracing（追踪）**，监控召回率/延迟/成本；建立**离线评估集 + 在线 A/B 测试**，发现 **Precision** 下降就调整分块或 Rerank。
