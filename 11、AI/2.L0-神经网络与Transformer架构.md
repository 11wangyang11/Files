# L0：AI 的“地基”——神经网络与 Transformer 架构

> 对应《1.全流程.md》第零层。这一层是所有概念的物理基础。不懂这层，上面四层都是“黑盒咒语”。
> 学习目标：搞懂“大模型到底是什么东西”。

---

## 一、神经网络基础：本质是一个“可调参数的大函数”

### 1.1 一句话理解
神经网络（Neural Network）本质就是一个巨大的、带有海量可调参数的数学函数：

```
输出 y = f(输入 x; 参数 θ)
```

“训练”就是不断调整参数 `θ`，让这个函数对“输入 → 输出”的映射越来越准。

### 1.2 核心零件
*   **神经元（Neuron）**：最小计算单元。做一件事：`output = 激活函数(Σ(输入 × 权重) + 偏置)`。
*   **权重（Weight）**：连接的“重要性”。模型学到的“知识”几乎全部存在权重里。所谓 7B 模型，就是有 70 亿个权重。
*   **偏置（Bias）**：一个可调的“基准偏移量”，让函数更灵活。
*   **激活函数（Activation Function）**：给网络加入“非线性”，否则再多层也只等于一层线性变换。
    *   **ReLU**：`max(0, x)`，简单高效，经典。
    *   **GELU / SwiGLU**：更平滑，Transformer 里常用。

### 1.3 为什么要“深”（多层）
*   单层只能学简单关系。多层堆叠后，**浅层学局部特征**（如笔画、词），**深层学抽象概念**（如语义、逻辑）。
*   “深度学习”里的“深”，指的就是层数多。

> 🔑 直觉：把神经网络想象成一条流水线，原始输入从一端进去，每一层都对它做一次“加工提炼”，最后一层吐出答案。

## 二、神经网络是怎么“学习”的（前向 + 反向传播）

这是理解 L1 训练的前置知识，先在这里建立直觉。

### 2.1 前向传播（Forward Propagation）
输入数据从前往后，逐层计算，最终得到一个预测输出。比如输入“今天天气真”，模型预测下一个词是“好”的概率最大。

### 2.2 计算损失（Loss）
把“预测输出”和“标准答案”对比，算出差距（Loss）。差距越大说明错得越离谱。

### 2.3 反向传播（Backpropagation）
这是深度学习的灵魂。从 Loss 出发，**反向**逐层计算“每个参数对误差贡献了多少”（即梯度），告诉每个权重“你应该往哪个方向调、调多少”。

### 2.4 参数更新
用**梯度下降**沿着“让 Loss 变小”的方向，把所有权重微调一点点。

> 🔁 整个过程：**前向算预测 → 算 Loss → 反向算梯度 → 更新权重**，循环亿万次，模型就“学会了”。（详细机制见 L1）

## 三、Transformer 架构：现代大模型的“发动机”

2017 年 Google 论文《Attention Is All You Need》提出 Transformer，奠定了如今所有大模型（GPT、Claude、DeepSeek、Llama）的基础。

### 3.1 它解决了什么问题
在 Transformer 之前，处理文本主流是 **RNN/LSTM**，缺点是：
*   **只能串行**，一个词一个词处理，慢，无法并行训练。
*   **长距离依赖差**，句子一长就“忘了前文”。

Transformer 用 **Attention 机制** 一举解决：可并行、能直接关联任意远的两个词。

### 3.2 整体结构（数据流）
一句话进入模型，经历如下流程：

```
文本 → Tokenizer 分词 → Embedding 向量化 → +位置编码
   → [ Attention 层 → 前馈网络 FFN ] × N 层  → 输出层 → 预测下一个 Token
```

*   **Tokenizer 分词**：在 Unicode 基础上按高频共现合并融合成子词词表，将文本转为整数 ID（中英文代码通用）。
*   **Embedding 层**：把每个 Token 变成一个向量（一串数字）。
*   **位置编码**：因为向量只管“是什么内容”不管“在哪个位置”，所以生成位置信号直接加到词向量上，强行注入先后次序。
*   **N 个 Transformer Block 堆叠**：每个 Block = 注意力 + 前馈网络（FFN）。层数越多模型越深越强。
*   **输出层**：把最后的向量映射回“词表概率分布”，选出下一个词。

## 四、Attention（注意力机制）：大模型的核心魔法 ⭐

这是整张地图最该吃透的一个概念。

### 4.1 直觉：读句子时“划重点”
读“**那只猫**没吃东西，因为**它**太累了”这句话时，你的大脑会自动把“它”关联到“猫”。Attention 做的就是这件事——**让模型在理解每个词时，自动判断该“关注”句子里的哪些其他词**。

> 💡 **“注意力”名字的由来**：之所以叫“注意（Attention）”，就是因为它让**每个词都能“注意到”序列里其他词的影响力**——按相关性给别的词分配不同的“关注度”。生成文本时，每个新字也是靠它去“注意”前面所有字（推理阶段的高效实现见 L2 的 KV Cache）。

### 4.2 Q / K / V 三剑客
Attention 把每个词变成三个向量，用“图书馆查资料”来类比：

| 角色 | 英文 | 类比 | 作用 |
| :--- | :--- | :--- | :--- |
| 查询 | **Query (Q)** | 你要查的“问题” | 当前词想找什么信息 |
| 键 | **Key (K)** | 每本书的“标签” | 别的词能提供什么信息 |
| 值 | **Value (V)** | 书里的“内容” | 别的词实际携带的信息 |

**计算流程**：
1.  用当前词的 **Q** 去和所有词的 **K** 做点积 → 得到“相关性分数”（谁和我更配）。
2.  分数经过 **Softmax** 归一化成“注意力权重”（加起来 = 1）。
3.  用这些权重去**加权求和所有词的 V** → 得到融合了上下文的新表示。

经典公式（看个眼熟即可）：

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
```

### 4.3 Self-Attention（自注意力）
Q、K、V 都来自**同一句话内部**——即句子里的每个词都去“看”句子里所有词（包括自己），从而理解上下文。这是 Transformer 的核心。

### 4.4 Multi-Head Attention（多头注意力）
不止一组 Q/K/V，而是并行用多组（多个“头”）。**每个头从不同角度理解句子**：有的头关注语法、有的关注指代、有的关注语义。最后把多个头的结果拼起来，理解更全面。

> 🔑 一句话总结：Attention 让模型“理解上下文”，多头让它“从多个角度同时理解”。这就是大模型能读懂复杂语境的根本原因。

## 4.5 实战串讲：跟着「苹果在哪？」走完整一遍 ⭐

> ⚠️ **视角声明（避免误解）**：本节走的是 **Decoder-Only（GPT 系）** 的完整流水线——因果掩码、预测下一个词、自回归循环。你日常用的 ChatGPT / Claude / DeepSeek Chat / Copilot，底层就是这条路。
>
> 前面第一～四节（除本节专属机制外）讲的 Tokenizer、Embedding、Attention Q/K/V 等，是三大流派**共用**的零件；**怎么组装、往哪输出**才分家。Encoder-Only（RAG 检索 / Embedding）走法见 **§4.6**；各节与三大流派的对照表见 **§七**。

> 把前面所有概念串成一条线：输入「苹果在哪？」，看模型如何一步步算出「在树上」。所有数字都是**为讲解极度简化的**（真实向量有几百上千维、几十上百层），重点是理解流程而非数值。

### 全程总览

```
苹果在哪？ →[分词+查表+位置编码]→ 词向量
          →[每层: 算Q/K/V → Q·K关注度 → 加权V → 新向量] × N 层
          → 取末字终向量 →[输出矩阵+Softmax]→ 每个字的概率
          →[采样]→ 出一个字「在」
          → 把「在」喂回，循环（自回归）→「树」→「上」→ 结束
最终输出：在树上
```

### Step 0：文字 → 数字（Embedding 查表）

模型有一本**词表**（每个 token 一个编号）和一张 **Embedding 表**（每个编号对应一行数字）。

```
苹果在哪？ →[分词]→ [苹][果][在][哪][？]   （假设 5 个 token）
苹 →[查词表]→ 编号3201 →[查Embedding表第3201行]→ x苹 = [1, 2]
```

*   `x苹` 就是“苹的词向量”的简写 = 查表取出的那串数字。
*   这张表的数字是**训练学出来的**：意思相近的词，向量也相近。
*   取出向量后再 **+ 位置编码**（告诉模型谁在第几位，见第五节），才正式进入下一步。

### Step 1：一个词向量 → Q、K、V（靠三个矩阵）

**矩阵 = 排成表格的一组「权重（Weight）」**，是模型训练出来、之后固定不变的“知识”（呼应 1.2 节）。同一个 `x苹`，乘三个不同矩阵，得到三个“分身”：

```
W_Q=[[1,0],[1,1]]   W_K=[[0,1],[1,0]]   W_V=[[1,1],[0,1]]
```

向量 × 矩阵算法：**新向量第 j 个数 = x 与矩阵第 j 列对应相乘再相加**。

```
Q苹 = x苹×W_Q = [1×1+2×1, 1×0+2×1] = [3, 2]   ← “提问”视角：我想找什么
K苹 = x苹×W_K = [1×0+2×1, 1×1+2×0] = [2, 1]   ← “标签”视角：我是什么
V苹 = x苹×W_V = [1×1+2×0, 1×1+2×1] = [1, 3]   ← “内容”视角：我能提供什么
```

> 每个字都同时有自己的 Q/K/V。**谁在被处理，谁就当“提问者”用自己的 Q；它去看的字（含自己）用各自的 K、V。**

### Step 2：关注度 = Q·K 点积 → Softmax

关注度不是新东西，**就是“当前字的 Q”点积“各字的 K”再归一化**。以「果」注意 苹、果 为例（设 Q果=[1,0]）：

```
分数(果→苹) = Q果·K苹 = 1×2+0×1 = 2.0   ← 越“配”分数越高
分数(果→果) = Q果·K果 = 1×0.5+0×1 = 0.5
   ↓ Softmax: e^2/(e^2+e^0.5) …
关注度: 苹≈0.8, 果≈0.2   （加起来=1）
```

*   **Q/K/V 是“一串数字”（向量）**；它们点积后塌缩成**“一个数字”（分数/关注度）**。
*   **因果掩码**：每个字只能注意自己和左边，不能偷看右边（保证“逐字生成”不作弊）。
*   **Softmax指数归一化**：Softmax 先对每个数取指数 e^x（指数函数的结果永远是正数），再去除以总和。最终得到一个既非负、又归一、且差距被放大（不会模棱两可）的概率分布。

### Step 3：用关注度加权 V → 新向量

```
果的新向量 = 0.8 × V苹 + 0.2 × V果
```

得到一个**融合了上下文的新向量**（产物仍是向量，不是字）。「果」至此“知道”自己前面是“苹”，合成了“苹果”。

### Step 4：为什么要算 N 层？

一层只是“读了一遍”，太浅。模型有 **N 层**，每层有**自己独立**的 W_Q/W_K/W_V，在上一层理解的基础上再加深一层。

**关键：槽位数不变，但每个槽“装的信息”越熬越浓。** 逐层追踪每个槽“脑子里装了啥”（因果掩码：只看自己和左边）：

| 层 | 苹槽 | 果槽 | 在槽 | 哪槽 |
| :-- | :-- | :-- | :-- | :-- |
| 第1层后 | {苹} | {苹,果} | {苹,果,在} | {苹,果,在,哪} |
| 第2层后 | 还是只含苹 | 更深的“苹果” | 间接吸到更全的“苹果在” | 间接吸到更完整组合 |
| …第N层 | — | — | — | **浓缩了“苹果在哪”整句意思** |

*   第 2 层注意的是**第 1 层已带上下文的向量**，不是原始孤立字 → 所以是“在更浓的汤里再熬”，而非重复同样的独立关联。
*   整句意思**不是合并成更少的槽**，而是**压缩进向量里**——尤其末字「？」的终向量，一个人扛着全句理解。
*   **N（层数）是“超参数”**：由人在训练前设定、固定不变（GPT-3 有 96 层）；模型训练时只学“矩阵里的数字（参数）”。层多→更聪明，但更慢更贵更难训（靠残差连接等稳住，见深挖清单）。
*   **W_Q96, W_K96, W_V96，与W_Q1, W_K1, W_V1**：是训练得到的固定矩阵。不同层级训练的矩阵不同，是因为不同层级的输入向量含义不同，越往深处输入越接近全部上下文。

> 类比：N 个人开 N 轮会。每轮发言后大家都听到了别人的观点，下一轮基于“已听过”再讨论，越讨论共识越深。人数（槽）不变，但认知越来越深。

### Step 5：N 层算完 → 预测下一个字（输出层）

```
取最后一个字的终向量（它浓缩了全句意思）
   ↓ × 输出矩阵（也是训练学的权重，常与 Embedding 表共享）
词表里每个字打一个分数(logit):
   在: 8.2   树: 3.1   上: 2.5   苹: -2.0   ...（词表多大就多少个分数）
   ↓ Softmax 变概率
   在: 0.55  树: 0.10  ...
   ↓ 采样策略（Temperature/Top-P，见 L2）挑一个
选出 →「在」   ← 第一个新字诞生（这才第一次蹦出“字”）
```

### Step 6：自回归循环 → 生成「在树上」

```
苹果在哪？        →[N层]→ 预测 →「在」
苹果在哪？在      →（Decode：靠 KV Cache 只算新字「在」）→ 预测 →「树」
苹果在哪？在树    →（只算「树」）→ 预测 →「上」
苹果在哪？在树上  →（只算「上」）→ 预测 →「<结束符>」→ 停
最终输出：在树上
```

*   **自回归**：吐一个字 → 接到序列末尾当新输入 → 再吐下一个 → 循环到结束符。
*   **KV Cache**：前面字的 K/V 在前面步骤已算好存着，Decode 时直接复用，只算新来的那一个字（详见 L2）。
*   **为什么能缓存**：因果掩码下，旧字永远看不到右边新字，所以旧字的 K/V 一旦算出**永不改变**——这正是 KV Cache 成立的根本原因。


### 全链条一图收尾

```
文字 →编号 →[Embedding查表]→ 词向量 x
   →×W_Q/W_K/W_V（权重矩阵）→ Q/K/V
   → Q·K →关注度(Softmax)→ 加权 V → 新向量
   →（重复 N 层，越熬越深，槽数不变、信息变浓）
   → 取末字终向量 →[输出矩阵+Softmax]→ 每个字的概率
   →[采样]→ 下一个字 → 喂回 → 循环（自回归）→ 直到结束
```

> 最底层的“矩阵”就是“权重”，绕回了第一节“神经网络 = 一堆权重”——整张知识网在此闭环。

## 4.6 对照串讲：同一句「苹果在哪？」，Encoder-Only 走哪条路 ⭐

> 用**同一句输入**对比 §4.5，看清 Decoder（生成）和 Encoder（理解）差在哪。代表模型：BERT、`bge-m3`、`text-embedding-3-small` 等 Embedding / 检索 / 分类模型。

### 全程总览（与 §4.5 逐步对照）

```
苹果在哪？ →[分词+查表+位置编码]→ 词向量          ← Step 0 完全相同
          →[每层: 算Q/K/V → Q·K关注度 → 加权V → 新向量] × N 层
              ↑ 无因果掩码：每个字能看整句（双向）   ← 与 §4.5 最大不同
          → 取 [CLS] 或 mean pooling → 一个句子向量  ← 不预测下一个字
          → 下游任务：
              · 向量检索（RAG）：和文档库向量算相似度
              · 文本分类：接一个小分类头 →「疑问句」
              · 不生成「在树上」
```

### Step 0～1：与 §4.5 相同

分词、Embedding 查表、位置编码、乘 W_Q/W_K/W_V 算 Q/K/V——**流程一模一样**，用的也是同一套 Attention 零件。

### Step 2：关注度计算——去掉因果掩码

§4.5 里「果」只能看「苹、果」（自己和左边）。Encoder-Only **没有这条限制**：

```
以「果」为例（双向 Attention）：
  分数(果→苹) = Q果·K苹 = 2.0
  分数(果→果) = Q果·K果 = 0.5
  分数(果→在) = Q果·K在 = 1.8   ← §4.5 里果看不到「在」，这里可以
  分数(果→哪) = Q果·K哪 = 0.3
  分数(果→？) = Q果·K？ = 0.1
   ↓ Softmax 归一化
  果的新向量 = 加权求和所有字的 V（含右边）
```

**直觉**：Decoder 像「边写边想，不能偷看后面」；Encoder 像「整篇文章开卷读完后做理解题」。

### Step 3～4：N 层堆叠——槽位信息变浓，但方式不同

| 层 | §4.5 Decoder（因果掩码） | §4.6 Encoder（双向） |
| :-- | :-- | :-- |
| 第 1 层后 | 每个槽只含「自己及左边」 | 每个槽已看过**整句** |
| 第 N 层后 | 末字「？」浓缩全句，为**预测下一字**服务 | 每个槽都含全句语义；常取 **[CLS]** 或 **mean pooling** 合成**一个句子向量** |

Encoder 训练时玩的是**完形填空（MLM）**：随机盖住一些词让模型猜（如「苹果 [MASK] 哪？」→ 猜「在」），所以必须双向看上下文——这和 §4.5「预测下一个词」是两种不同的训练游戏。

### Step 5：输出——不是「逐字生成文字」，而是向量 / 标签 / 检索结果

> ⚠️ **常见误解**：「不生成文字」≠「没有输出」。Encoder **有输出**，只是输出的是 **数学向量、分类标签、检索到的文档片段**——不是像 ChatGPT 那样一个字一个字往外吐自然语言。

```
N 层算完
   ↓ 取 [CLS] 向量（或所有字向量求平均）
句子向量 = [0.12, -0.45, 0.88, ...]   （几百～几千维）  ← 这就是 Encoder 的「产出」
   ↓ 下游用法（三选一；都不逐字生成，但都有明确输出）
  ┌─ RAG 检索：和问题向量算余弦相似度 → 输出「最相关的 Top-K 文档块」（仍是文字，但是从库里捞出来的，不是模型写的）
  ├─ 文本分类：向量 × 小分类矩阵 → Softmax → 输出标签「疑问句 / 陈述句 / …」
  └─ 相似度：两句分别取向量 → 比较距离 → 输出一个分数（多相近）
```

**没有**「采样出一个字 → 喂回 → 循环」——Encoder **天生不逐字生成**，但 **一次前向就会给出向量 / 标签 / 检索结果**。

**RAG 完整链路里 Encoder 干什么、输出什么**：

```
用户问「怎么退款？」
   │
   ├─ 🔵 Encoder（§4.6 这一步）
   │     输入：用户问题
   │     输出：问题向量 + 从向量库匹配到的 Top-3 文档块（如《退款政策》第 2 节原文）
   │     ← 注意：这里输出的是「找资料」，不是「写回答」
   │
   └─ 🟢 Decoder（§4.5）
         输入：Top-3 文档块 + 用户问题（拼成 Prompt）
         输出：「根据退款政策，您可在 7 天内……」（模型逐字生成的自然语言）
```

> 🔑 一句话：**Encoder 负责「找对资料」，Decoder 负责「组织成回答」**——RAG 缺了 Encoder 就找不到库里的文档，缺了 Decoder 就只能把原文甩给用户、没法用人话总结。

### 一图对比两条流水线

```
                    ┌── 公共前半段 ──┐
文字 → Tokenizer → Embedding + 位置编码 → N 层 Attention + FFN
                    └── 公共前半段 ──┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
     §4.5 Decoder-Only                §4.6 Encoder-Only
     因果掩码（只看左边）               双向（看整句）
     末字向量 → 词表概率               [CLS]/mean → 句子向量
     采样 → 逐字生成「在树上」           检索 / 分类 / 相似度
     自回归循环                         一次前向，结束
              │                               │
              ▼                               ▼
     ChatGPT / Claude / 写代码          RAG 检索 / Embedding API
```

> 🔑 **RAG 其实是两条路拼起来**：文档和用户问题先用 **Encoder** 变成向量做检索（§4.6），检索到的段落再交给 **Decoder** 组织语言回答（§4.5）。

## 五、位置编码（Positional Encoding）

### 5.1 为什么需要
Attention 本身是“无序”的——它同时看所有词，并不知道谁先谁后。但“狗咬人”和“人咬狗”意思完全不同！所以必须额外告诉模型**每个词的位置**。

### 5.2 主流做法
*   **绝对位置编码**：给每个位置一个固定/可学习的向量（原始 Transformer 用三角函数）。
*   **RoPE（旋转位置编码）**：当今主流（Llama、DeepSeek 都用），用“旋转向量”表示相对位置，更利于扩展长上下文。

## 六、Token 与 Tokenizer（词元与分词器）⭐

这是后面 L2/L4 “成本”和“上下文长度”的根源，必须搞懂。

### 6.1 Token 不是“字”
模型不直接读字符，而是读 **Token（词元）**——由 **Tokenizer** 切分出的片段。
*   英文：常见单词 ≈ 1 个 Token，复杂词被拆成几个（如 `tokenization` → `token` + `ization`）。
*   中文：1 个汉字通常 ≈ 1~2 个 Token。
*   经验值：**1 个英文 Token ≈ 4 个字符 ≈ 0.75 个英文单词**。

### 6.2 BPE（Byte Pair Encoding）分词算法
主流分词算法。核心思想：**从字符开始，反复把“最常一起出现的相邻片段”合并成新 Token**，直到词表达到设定大小。这样既能覆盖常见词（高效），又能拼出生僻词（不会“不认识”）。

### 6.3 为什么这事很重要
*   **按 Token 计费**：调 API 花的钱 = 输入 Token + 输出 Token。
*   **按 Token 算上下文**：模型“上下文窗口 128K”指的是 12.8 万个 Token，不是字数。
*   **影响多语言成本**：同样意思，中文/小语种往往比英文耗更多 Token，更贵。

> 🛠️ 实操：可用 OpenAI 的 `tiktoken` 库实际数一段文字有多少 Token。

### 📋 读前须知：L0 知识分层地图

> 读完全文容易默认「全世界都是 GPT 那种模型」——其实 L0 约 **70% 是公共地基**，**30% 默认 Decoder 视角**（§4.5 实战、自回归、Scaling Law 例子）。用下面三层地图定位自己用的工具。

                            │ 组装方式不同
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼

  双向理解               单向生成            先理解再生成
        │                   │                   │

### 7.1 三大流派概览

2017 年原始 Transformer = **Encoder + Decoder 合体**。后来拆成三种用法：

| 流派 | 代表 | Attention 方向 | 训练目标 | 擅长 | 现状 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Decoder-Only** | GPT、Claude、Llama、DeepSeek | 单向（因果掩码） | 预测下一个词 | 生成 / 续写 / 对话 | ✅ 当今绝对主流 |
| **Encoder-Only** | BERT、bge-m3 | 双向（看整句） | 完形填空（MLM） | 理解 / 分类 / Embedding | 仍用于检索、分类 |
| **Encoder-Decoder** | T5、BART | Encoder 双向 + Decoder 单向 + **跨注意力** | 输入序列→输出序列 | 翻译 / 摘要 | 特定任务用 |

### 7.2 核心差异：同一零件，三种组装

Attention 的 Q/K/V 算法（第四节）三家一样，**变的是 Softmax 前的 Mask 和最终输出**：

```
Encoder（BERT）：  每个词能看  ← 自己 →  全部词     →  输出向量 / 分类
Decoder（GPT）：   每个词只能看  ← 自己              →  逐字生成文本
Enc-Dec（T5）：    先 Encoder 读输入，Decoder 写输出  →  输入段→输出段
                   （Decoder 还通过 Cross-Attention「看」Encoder 的表示）
```

| 维度 | Encoder-Only | Decoder-Only | Encoder-Decoder |
| :--- | :--- | :--- | :--- |
| **Attention** | 双向 Self-Attention | 因果 Self-Attention | 双向 Encoder + 因果 Decoder + Cross-Attention |
| **训练游戏** | 完形填空（猜被遮住的词） | 接龙（猜下一个词） | 给定输入段，生成输出段 |
| **推理输出** | 向量 / 标签（一次前向） | 文本（自回归循环） | 文本（Decoder 逐字写，参考 Encoder） |
| **实战串讲** | §4.6 | §4.5 | 无单独串讲（可理解为 §4.6 读输入 + §4.5 写输出） |

### 7.3 为什么 Decoder-Only 赢了
*   **任务统一**：万物皆可变成“预测下一个词”，一个架构通吃问答、翻译、写代码、推理。
*   **训练简单 + 易扩展**：无监督预训练数据无限（全网文本），配合 Scaling Law 越大越强。
*   **涌现能力**：规模够大后自动学会推理、In-Context Learning（看几个例子就会）。

> 关键机制：Decoder 用 **因果掩码（Causal Mask）**，保证预测第 N 个词时只能看到前面的词，不能“偷看答案”，这才符合“逐字生成”的逻辑。

## 八、参数量（Parameters）与显存

*   **参数量** = 模型里权重的总数。`7B` = 70 亿，`70B` = 700 亿。
*   一般规律：**参数越多 → 越聪明 → 越吃显存、越慢、越贵**。
*   **显存估算（粗算）**：FP16 精度下，每个参数占 2 字节。7B 模型 ≈ 14GB 显存才能加载（推理）；训练还要数倍。这就是 **量化（INT8/INT4）** 存在的意义（见 L4）。

## 九、MoE（Mixture of Experts，混合专家）

### 9.1 解决的问题
传统“稠密模型”：每生成一个词都要动用**全部**参数，又慢又贵。

### 9.2 MoE 的巧思
把 FFN 拆成很多个“专家（Expert）”，再加一个**路由器（Router/Gating）**。每个 Token 只激活其中**少数几个专家**（如 8 选 2）。
*   **总参数量很大**（知识储备足，比如 DeepSeek-V3 有 671B），
*   **但每次只激活一小部分**（推理快、便宜，实际激活仅 37B）。

> 🔑 一句话：MoE = “大而专”，用很大的总容量换知识，用很小的激活量换速度。DeepSeek、Mixtral、GPT-4 都用了它。

---

## 十、Scaling Law（缩放定律）与涌现能力

### 10.1 Scaling Law（缩放定律）
模型性能与 **参数量、数据量、算力** 三者呈可预测的幂律关系。简单说：**只要三者一起按比例放大，模型就会稳定变强**。这是“大力出奇迹”有理论支撑的原因。

### 10.2 涌现能力（Emergent Ability）
当模型规模跨过某个临界点，会**突然“开窍”**，出现小模型完全没有的能力，比如：
*   多步推理、做数学题
*   In-Context Learning（看几个例子就会模仿）
*   思维链（CoT）

> ⚠️ 注意：学界对“涌现是真突变还是评估指标的错觉”仍有争论，但“规模带来质变”这个现象本身是公认的。

## 📌 本章小结：理解大模型的“一句话链条”

**公共地基（所有流派共用）**：
> 文本被 **Tokenizer** 切成 **Token** → 变成 **Embedding 向量** → 加 **位置编码** → 经过 N 层 **Transformer（核心是 Attention + FFN）** 反复提炼上下文。

**Decoder-Only 专属后半段（ChatGPT 等）**：
> 因果掩码 → 取末字向量 → 输出层预测**下一个 Token** → 逐字生成完整回答（§4.5）。

**Encoder-Only 专属后半段（RAG 检索等）**：
> 双向 Attention → 取 **[CLS] / mean pooling** → 得到**句子向量** → 检索 / 分类 / 相似度（§4.6）。

> 模型的“知识”全部存在 **权重（参数）** 里；**Scaling Law** 说明 Decoder 类大模型只要够大就够强；**MoE** 让“又大又快”成为可能。

## 🔬 深挖清单详解（逐条讲透）

> 对应《1.全流程.md》L0 的「深挖清单 ✅」，这里把每一条都展开。

### 1）神经网络是怎么“学习”的（前向 / 反向传播直觉）
学习 = **不停地“试错—纠错”**，循环四步：
1.  **前向传播**：数据从输入层流到输出层，得到一个预测。
2.  **算 Loss**：预测和正确答案比，差多少。
3.  **反向传播**：从 Loss 倒推，算出“每个权重该为这个错误负多少责任”（梯度）。
4.  **更新**：每个权重朝“减小错误”的方向挪一小步。
> 类比：射箭脱靶（前向）→ 看偏多远（Loss）→ 分析是手抖还是风大（反向求梯度）→ 微调姿势（更新），射亿万次就成神射手。

### 2）Transformer 整体结构图（Embedding → Attention → FFN → 输出）
```
输入文本
  │  Tokenizer 分词
  ▼
[Token IDs]
  │  Embedding 查表 + 位置编码
  ▼
[词向量序列] ───────────────┐
  │                          │  重复 N 层
  ▼                          │
┌─────────────────────────┐ │
│ Multi-Head Attention     │ │  ← 词与词互相“看”，融合上下文
│   + 残差 & LayerNorm     │ │
│ Feed-Forward (FFN)       │ │  ← 对每个词做非线性“深加工”
│   + 残差 & LayerNorm     │ │
└─────────────────────────┘ │
  │ ◄──────────────────────┘
  ▼
输出层 (Linear + Softmax)
  ▼
下一个 Token 的概率分布
```
*   **Attention**：负责“词与词之间交流信息”（横向）。
*   **FFN（前馈网络）**：负责“对单个词的信息做深度提炼”（纵向）。
*   **残差连接 + LayerNorm**：让几十上百层能稳定训练、不“失忆”。

### 3）Attention 的 Q/K/V 到底是什么
每个词生成三份向量（由三个可学习矩阵乘出来）：
*   **Q（Query 查询）**：我（当前词）想找什么信息。
*   **K（Key 键）**：我能被什么样的查询匹配到（我的“标签”）。
*   **V（Value 值）**：如果你匹配到我，我能给你什么内容。

计算：`当前词的Q` 和 `所有词的K` 做点积 → 得分 → Softmax 成权重 → 用权重对所有词的 `V` 加权求和。
> 即“用我的问题去匹配大家的标签，谁标签越对得上，就越多地吸收谁的内容”。这就是上下文理解的本质。

### 4）为什么是 Decoder-Only 赢了（vs BERT）
*   **BERT（Encoder-Only）**：“完形填空”式训练（盖住中间词让它猜），擅长理解，但**不会生成连贯长文本**。走法见 **§4.6**。
*   **GPT（Decoder-Only）**：“预测下一个词”式训练，**天生会生成**。走法见 **§4.5**。
*   **RAG**：Encoder 做检索（§4.6）+ Decoder 做生成（§4.5），两条流派拼接。
*   赢的三个原因：① **任务统一**——翻译/问答/写代码全能表示成“预测下一个词”；② **训练数据无上限**（全网文本天然是训练样本）；③ 规模一大就出现 **In-Context Learning / 涌现能力**。
> 简言之：Decoder-Only 用一种简单范式通吃所有任务，又能无限喂数据，配合 Scaling Law 一路做大变强。L0 知识分层与各节对照见 **§七**。

### 5）Tokenizer 与 BPE：一句中文/英文分别是多少 Token
*   **BPE 原理**：从单字符起步，反复把“出现最频繁的相邻组合”合并成新 Token，直到词表满。常见词成整块、生僻词被拆分，兼顾效率与覆盖。
*   **经验换算**：英文 1 Token ≈ 4 字符 ≈ 0.75 个单词；中文 1 个汉字 ≈ 1~2 Token。
*   **举例（约数）**：
    *   `"Hello, world!"` ≈ 4 Token。
    *   `"我爱自然语言处理"` ≈ 8~12 Token。
*   **影响**：直接决定 API 费用和上下文占用；中文/小语种通常比英文更耗 Token。可用 `tiktoken` 实测。

### 6）MoE（混合专家）：为什么 DeepSeek/Mixtral 又快又强
*   **结构**：把 FFN 换成“很多个专家 + 一个路由器”。每个 Token 只被路由到**少数几个专家**（如 256 选 8）。
*   **又强**：总参数极大（知识容量足，如 DeepSeek-V3 671B）。
*   **又快**：每个 Token 只激活一小部分参数（如仅 37B 参与计算），算得少、便宜。
> 一句话：**“总容量按大模型算，计算量按小模型算”**——用稀疏激活换来“大而快”。代价是显存仍要装下全部专家、训练时负载均衡难调。
