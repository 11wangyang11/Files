# L1：模型的“孕育”与“调教”——训练与微调

> 对应《1.全流程.md》第一层。这一层决定了 AI 的“智商”和“知识储备”。
> 学习目标：搞懂一个“野生天才”是如何被一步步训练成“听话的 ChatGPT”的。

---

## 〇、全景：从 0 到 ChatGPT 的四步流水线

```
海量全网文本 ──预训练(Pre-training)──▶ 基座模型(Base)  「会接话的野生天才」
                                          │
                          ──SFT(监督微调)──▶ 会按“问-答”格式回话
                                          │
                ──RLHF / DPO(对齐)──▶ 说人话、守价值观  「ChatGPT」
                                          │
              ──Fine-tuning(领域微调,可选)──▶ 某垂直领域专家  「你的客服模型」
```

> 🔑 记住这条主线：**预训练（给知识）→ SFT（教格式）→ 对齐（调三观）→ 微调（补专业）**。

---

## 一、预训练（Pre-training）：造一个“有常识的大脑”

### 1.1 在做什么
喂给模型**海量数据**（全网公开文本，数万亿 Token），让它玩一个游戏：**预测下一个词（Next Token Prediction）**。

例如给 “中国的首都是”，让它预测 “北京”。为了把这个游戏玩好，模型被迫学会了语法、事实、逻辑、甚至代码——**世界知识被“压缩”进了权重里**。

### 1.2 关键特征
*   **自监督学习**：不需要人工标注，文本本身就是答案（下一个词），所以数据可以无限大。
*   **成本极高**：这就是“几千亿次计算”的源头，动辄几百上千万美元、几千张 GPU 训几个月。
*   **产物：基座模型（Base Model）**。像个“野生天才”——知识渊博、会续写，但**不一定听你的话**（你问它问题，它可能给你续写出更多问题）。

---

## 二、SFT（Supervised Fine-Tuning，监督微调）：教它“好好说话”

### 2.1 在做什么
用**人工编写的“问答对”（Instruction-Response）** 来训练基座模型，让它学会“**你提问，我按格式回答**”的对话范式。

数据样例：
```
指令: 帮我写一首关于春天的诗。
回答: 春风拂面花满枝，...（高质量的人工示范答案）
```

### 2.2 关键点
*   这是从“野生”到“家养”的**第一步**。
*   **数据质量 ≫ 数据数量**：几万条高质量、多样化的指令数据，往往胜过几百万条粗糙数据。
*   产物：一个会“听指令”的模型，但回答的“好坏偏好”还没对齐人类。

---

## 三、对齐（Alignment）：调好“三观”，让它说“人话”

SFT 只教了“格式”，但同一个问题可能有很多种回答，**哪个更好、更安全、更符合人类偏好？** 这需要“对齐”。

### 3.1 RLHF（人类反馈强化学习）—— 经典方案

三步走：
1.  **采集偏好数据**：同一问题让模型生成多个答案，人工排序“哪个好哪个差”。
2.  **训练奖励模型（Reward Model, RM）**：用偏好数据训练一个“裁判模型”，它能给任意答案打分（越符合人类喜好分越高）。
3.  **强化学习（PPO）**：让主模型不断生成答案，奖励模型打分，主模型为了“拿高分”逐步调整，最终学会说人话、守规矩。

> 这就是 **ChatGPT 比普通基座模型更“懂事”** 的核心秘密。
> ⚠️ 缺点：要训练额外的 RM，PPO 流程复杂、不稳定、调参难。

### 3.2 DPO（Direct Preference Optimization，直接偏好优化）—— 新主流

*   **核心改进**：跳过“训练奖励模型 + 强化学习”这套复杂流程，**直接**用“好答案 vs 坏答案”的偏好数据，通过一个简单的损失函数来优化模型。
*   **优点**：工程上更简单、更稳定、更省资源。
*   现在很多开源模型（如 Llama、Mistral 系）对齐都用 DPO 或其变体（如 KTO、ORPO）。

> 🔑 一句话对比：**RLHF = 请个裁判反复给你打分练习；DPO = 直接背“正确答案对比”自我纠正**。效果接近，DPO 更省事。

---

## 四、微调（Fine-tuning）：把通用模型变成“领域专家”

### 4.1 在做什么
用**公司内部 / 特定领域数据**（客服对话记录、法律文书、特定代码库）给已经对齐好的模型“补课”，让它精通某个垂直领域。

*   相比预训练，微调成本**极低**（几张 GPU、几小时）。
*   典型用途：让模型学会公司话术、专业术语、特定输出格式。

### 4.2 全参微调 vs PEFT

| 方式 | 改多少参数 | 成本 | 适用 |
| :--- | :--- | :--- | :--- |
| **全参微调（Full Fine-tuning）** | 改全部权重 | 极高（显存吃满） | 资源充足、要深度定制 |
| **PEFT（参数高效微调）** | 只改一小部分 | 低 | ✅ 中小团队首选 |

### 4.3 LoRA（Low-Rank Adaptation）⭐

PEFT 的当红代表，**必须掌握**。

*   **核心思想**：冻结原模型所有权重不动，只在旁边**外挂两个小矩阵（低秩矩阵 A、B）** 来学习“改动量”。训练时只更新这两个小矩阵。
*   **为什么有效**：研究发现微调时权重的“改动量”其实是“低秩”的（信息冗余多），用小矩阵就能很好近似。
*   **好处**：
    *   训练参数量减少 99%+，**单张消费级显卡就能微调**。
    *   一个基座可以挂多个 LoRA“插件”，按需切换（客服 LoRA、写作 LoRA…），不用存多份大模型。

### 4.4 QLoRA

在 LoRA 基础上，再把**基座模型量化到 4-bit**（见 L4 量化）加载，进一步把显存需求砍到极致。**一张 24G 显卡微调几十 B 模型**成为可能。这是中小团队/个人微调的事实标准方案。

> 🛠️ 实操工具：HuggingFace 的 `peft`、`trl` 库，`Unsloth`（加速），`LLaMA-Factory`（一站式微调框架）。

## 五、训练核心机制（每个都该有直觉）

这些是“模型如何学习”的内部齿轮，结合 L0 的“前向/反向传播”一起理解。

### 5.1 损失函数（Loss Function）
衡量“模型预测”与“标准答案”的差距。语言模型常用 **交叉熵损失（Cross-Entropy）**。训练目标就是：**让 Loss 越来越小**。

### 5.2 梯度下降（Gradient Descent）+ 优化器（Optimizer）
*   **梯度**：Loss 对每个参数的“偏导”，指明“往哪调能让 Loss 变小”。
*   **梯度下降**：沿梯度反方向，把参数挪一小步。形象比喻：**蒙眼下山，每一步都朝最陡的下坡方向走**。
*   **优化器**：决定“怎么走更聪明”。**Adam / AdamW** 是大模型标配（带动量、自适应步长，又快又稳）。

### 5.3 学习率（Learning Rate）⭐
**每一步走多大**。最关键的超参数之一：
*   太大 → 在山谷里反复横跳，永远到不了底（震荡/发散）。
*   太小 → 走得太慢，训练巨慢，还可能卡在小坑里。
*   实践常用 **Warmup（先小后大）+ 衰减（后期变小）** 的调度策略。

### 5.4 Epoch / Batch Size / Step
*   **Batch（批）**：一次喂给模型多少条数据一起算。
*   **Step（步）**：处理完一个 Batch、更新一次参数。
*   **Epoch（轮）**：把整个训练集完整过一遍。

## 六、过拟合 / 欠拟合：训练里最常见的“病”

| 现象 | 表现 | 类比 | 解决 |
| :--- | :--- | :--- | :--- |
| **欠拟合（Underfitting）** | 训练集都学不好 | 没学会，基础太差 | 加大模型/多训练/换特征 |
| **过拟合（Overfitting）** | 训练集高分、测试集低分 | 死记硬背，不会举一反三 | 见下方手段 |

### 对抗过拟合的常用手段
*   **更多 / 更多样的数据**（最有效）。
*   **正则化（Regularization）**：L1/L2，限制权重别太大。
*   **Dropout**：训练时随机“关掉”一部分神经元，逼模型别依赖个别神经元。
*   **早停（Early Stopping）**：验证集 Loss 不降了就停。

> 🔑 判别口诀：**训练好+测试差 = 过拟合；训练就差 = 欠拟合。**

## 七、模型评估：怎么知道模型“行不行”

### 7.1 数据集三分（铁律）
*   **训练集（Train）**：用来学。
*   **验证集（Validation）**：调超参、选模型。
*   **测试集（Test）**：最终考试，**绝不能在训练中见过**，否则就是“作弊/数据泄露”。

### 7.2 分类指标（你问过的 Precision/Recall）

以“判断邮件是否垃圾邮件”为例：

*   **Precision（精确率）**：模型说是垃圾的里面，真有多少是垃圾。**低 → 误报多**（总把正常邮件当垃圾删了）。
    *   `Precision = TP / (TP + FP)`
*   **Recall（召回率）**：所有真垃圾里，被抓出来多少。**低 → 漏报多**（垃圾邮件溜进收件箱）。
    *   `Recall = TP / (TP + FN)`
*   **F1-Score**：Precision 和 Recall 的调和平均，二者综合。
    *   `F1 = 2 · P · R / (P + R)`
*   **权衡**：通常二者此消彼长。宁可错杀（重 Recall，如疾病筛查）还是宁可放过（重 Precision，如推荐），取决于业务。

### 7.3 大模型专属评估
*   **Perplexity（困惑度）**：衡量模型对文本的“意外程度”，越低说明语言建模越好。
*   **Benchmark 榜单**：**MMLU**（综合知识）、**GSM8K**（数学）、**HumanEval**（写代码）等标准考卷。
*   **LLM-as-a-Judge**：用更强的大模型（如 GPT-4）当裁判给答案打分，省人力、可规模化（但要防裁判偏见）。

## 八、知识蒸馏（Knowledge Distillation）

*   **目标**：把一个“大而强”的**教师模型**的能力，“浓缩”进一个“小而快”的**学生模型**。
*   **做法**：让学生模型不只学“标准答案”，还学教师模型输出的“概率分布（软标签）”，相当于学到了教师的“思考方式”。
*   **价值**：小模型部署便宜、推理快，却保留了大模型的大部分能力。很多开源小模型（如 DeepSeek-R1-Distill 系列）就是这么来的。

---

## 📌 本章小结
> **预训练**用海量文本喂出“有知识的野生大脑（Base）”；**SFT** 教它按问答格式说话；**RLHF/DPO** 把它的偏好对齐到人类；**Fine-tuning（尤其 LoRA/QLoRA）** 把它变成领域专家。
> 训练的内核是 **前向→Loss→反向→梯度下降更新** 的循环，关键旋钮是**学习率**，最大的坑是**过拟合**，最终用 **Precision/Recall/F1 + Benchmark** 来检验。

## 🔬 深挖清单详解（逐条讲透）

> 对应《1.全流程.md》L1 的「深挖清单 ✅」。

### 1）预训练 → SFT → RLHF/DPO 的完整数据流
| 阶段 | 数据形式 | 数据来源 | 学到什么 |
| :--- | :--- | :--- | :--- |
| 预训练 | 纯文本（无标注） | 全网爬取、书籍、代码 | 世界知识、语言规律 |
| SFT | (指令, 优质回答) 对 | 人工编写/标注 | 听指令、按问答格式说话 |
| RLHF/DPO | (指令, 好答案, 坏答案) 偏好对 | 人工对模型输出排序 | 对齐人类偏好与价值观 |
> 数据流：原始文本喂出 Base → 几万条指令对做 SFT → 几万条偏好对做对齐。**越往后数据越少越精，但越贵越关键。**

### 2）LoRA 原理（为什么一个“低秩补丁”就够用）
*   原始权重是个大矩阵 `W`（如 4096×4096）。微调本想学一个“改动量” `ΔW`，但它也很大。
*   **关键发现**：`ΔW` 其实是“低秩”的——信息冗余，可用两个瘦长小矩阵相乘近似：`ΔW ≈ B·A`（`B` 是 4096×r，`A` 是 r×4096，`r` 取 8/16 这种小数）。
*   训练时**冻结 W，只学 A、B**。参数量从 1600 万降到几万，省 99%+。
*   推理时把 `B·A` 加回 `W` 即可，**不增加延迟**。
> 类比：不重写整本书，只在书页上贴几张“小修正便利贴”。

### 3）梯度下降 + 反向传播的直觉理解
*   **目标**：找让 Loss 最小的参数 = 在“误差地形”里找最低谷。
*   **梯度**：当前点最陡的上坡方向；**反方向**就是下坡最快方向。
*   **反向传播**：用链式法则，从输出层往输入层**逐层把“误差责任”分摊到每个权重**，高效算出所有梯度。
*   **下降**：`新权重 = 旧权重 − 学习率 × 梯度`，挪一小步。
> 类比：蒙眼下山，用脚感受最陡下坡方向（梯度），迈一步（学习率），反复直到谷底。

### 4）过拟合的识别与解决（训练集高分、测试集低分）
*   **识别**：训练 Loss 一直降、验证 Loss 先降后升（开始“背题”）；或训练 99 分、测试 60 分。
*   **解决（按性价比排序）**：① 加更多/更多样数据；② 数据增强；③ 早停（Early Stopping）；④ Dropout；⑤ L1/L2 正则；⑥ 减小模型或减少训练轮数。
> 微调场景最常见的过拟合：数据太少+训练太多轮，模型把训练样本背下来了，换个问法就崩。

### 5）知识蒸馏（Distillation）：大模型如何教出小模型
*   **教师**（大模型）对每个输入输出一个**概率分布（软标签）**，比如“猫 70% / 虎 25% / 狗 5%”——这比硬标签“猫”含的信息多（它表达了“像虎多于像狗”）。
*   **学生**（小模型）同时学**软标签 + 真实标签**，相当于继承了老师的“判断倾向/思路”。
*   产物：小模型体积小、推理快、便宜，却保留大模型大部分能力。DeepSeek-R1-Distill、众多端侧小模型都这么来的。

### 6）数据质量 > 数据数量：高质量数据集如何构造
*   **多样性**：覆盖任务类型、领域、提问风格，避免分布单一。
*   **正确性**：答案准确、无事实错误、无有害内容。
*   **格式一致**：统一的指令-回答结构，符合期望输出风格。
*   **难度梯度**：包含简单到复杂样本。
*   **去重 & 去污染**：删重复样本，确保测试集没混进训练集。
> 业界共识（如 LIMA 实验）：**1000 条精挑细选的数据 > 几十万条噪声数据**。微调时先死磕数据质量，再谈数量。
